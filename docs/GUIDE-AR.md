# دليل تشغيل وشرح مشروع دعم العملاء

## 1. فكرة المشروع التي تشرحها للمهندس

المشروع بوابة دعم فني لعملاء شركة لديها عدة أنظمة. العميل يفتح تذكرة ويحدد المنتج والمشكلة والمرفقات. المدير يعيّن موظف الدعم، والموظف والعميل يتبادلان الردود داخل نفس التذكرة. بعد الحل يؤكد العميل، ثم يغلق الموظف التذكرة. لكل دور صلاحيات مستقلة يطبقها الباك، وليس مجرد إخفاء أزرار بالواجهة.

**نفس التذكرة تستقبل عدة رسائل:** افتح التذكرة، اكتب في Your message، واضغط Send comment. يبقى الرقم نفسه. Edit ticket يعدّل وصف التذكرة والمنتج قبل إغلاقها. New ticket أو Create another ticket ينشئ طلبًا مستقلًا برقم جديد. لا توجد تذاكر فرعية لها حالات مستقلة داخل التذكرة؛ طلب المستخدم الأخير هو محادثة ومتابعات بنفس الرقم، وهي موجودة.

## 2. فتح وتشغيل النسخة الموجودة على جهازك بسرعة

في VS Code: File ثم Open Folder واختر:

```text
C:\Users\USER\OneDrive\Desktop\Client Support Ticketing System
```

افتح تيرمنل للباك:

```powershell
cd "C:\Users\USER\OneDrive\Desktop\Client Support Ticketing System\Backend\Client Support Ticketing System\Client Support Ticketing System"
dotnet run -- --urls "https://localhost:7200;http://localhost:5110"
```

افتح تيرمنل ثاني للفرونت:

```powershell
cd "C:\Users\USER\OneDrive\Desktop\Client Support Ticketing System\Frontend"
npm start
```

افتح http://localhost:4200/login واترك التيرمنلين يعملان. فحص الباك: https://localhost:7200/api/health. شرح وتجربة الـAPI: https://localhost:7200/swagger في وضع Development.

إذا ظهر خطأ DLL مستخدم: أوقف نسخة الباك القديمة بـCtrl+C أو أوقف Debugging في Visual Studio، ثم أعد التشغيل. بعد تعديل إعدادات البريد أعد تشغيل الباك. إذا ظهر Connection refused تأكد من تشغيل الباك والفرونت والمنافذ المذكورة. لا تستخدم نسخة ZIP القديمة باعتبارها آخر تعديلات.

هذه الأوامر تخص جهازك الحالي. تشغيل نسخة GitHub على جهاز جديد يحتاج إعداد SQL Server والاتصال والمفتاح وقاعدة البيانات والحزم؛ الخطوات في README.md.

## 3. عرض سريع أمام المهندس

1. سجّل دخول بحساب العميل. افتح My tickets ثم تذكرة موجودة.
2. اكتب متابعة في Your message واضغط Send comment. أشر إلى أن رقم التذكرة بقي كما هو.
3. افتح New ticket فقط لشرح مشكلة مستقلة. يمكن بقاء عدة تذاكر مفتوحة معًا.
4. افتح My account: الاسم والرقم والعنوان والصورة. تغيير كلمة المرور يحتاج الحالية. تغيير البريد يحتاج تأكيد البريد الجديد.
5. سجّل دخول كمدير. اعرض قائمة العملاء والموظفين، الفلاتر، وتعيين موظف للتذكرة.
6. سجّل دخول بالموظف المعين، واعرض التذكرة ورد عليها.
7. اعرض تأكيد الحل من العميل ثم الإغلاق من الموظف.
8. افتح Dashboard كمدير واضغط Refresh لعرض أثر البيانات.

استخدم حسابات العرض التي تملكها. كلمة مرور العميل الذي استعاد حسابه هي آخر كلمة اختارها، وليست بالضرورة كلمة الاختبار الأولى. لا تستخدم كلمة مرور Gmail لتسجيل الدخول للمشروع.

## 4. كيف أضع بيانات على Dashboard؟

الداشبورد تقرأ البيانات من الباك عبر GET /api/dashboard. لإنشاء مثال واقعي: أنشئ تذكرة جديدة فتزيد تذاكر New، ثم عيّن موظفًا فتظهر ضمن التذاكر المعينة. بعد دورة الحل والتأكيد والإغلاق تزيد Closed. إضافة عميل أو موظف تؤثر على العدادات. الرسائل نفسها لا تنشئ تذاكر جديدة ولا تزيد عدد التذاكر. الرسم الشهري يعتمد على تاريخ الإنشاء، لذلك تذاكر اليوم تظهر بالشهر الحالي.

ترتيب الموظفين مبني على عدد التذاكر حسب الحساب الموجود في الباك، وليس تقييمًا شاملًا لأداء الموظف. بيانات المنتجات في هذا المشروع تُجهّز بقاعدة البيانات؛ ليست هناك شاشة إضافة/حذف منتج، ولم تكن مطلوبة صراحةً في مستند المدرب.

## 7. المتبقي قبل التسليم

- الكود موجود، والبناء والاختبارات السابقة نجحت. المستخدم أكد استعادة كلمة المرور وتغيير الاسم؛ بعض عمليات الحساب الجديدة تحتاج تجربة نهائية أمام المتصفح.
- جرّب إرسال رسالتين داخل نفس التذكرة ثم تحديثها؛ يجب أن يظهر الاثنان والرقم نفسه.
- راجع تغيير الرقم والصورة وإزالتها وتغيير كلمة المرور من الحساب وتأكيد بريد جديد.
- استبدل كلمات مرور تطبيق Gmail التي ظهرت في صور المحادثة، واحفظ الجديدة محليًا فقط.
- لا ترفع appsettings أو أسرار البريد أو App_Data أو نسخة .bak إلى GitHub. نسخ البيانات والمرفقات إن لزم تسليمها تُشارك بشكل خاص منفصل.
- .NET 6 خارج الدعم، وفحص الثغرات الكامل وتشغيل نسخة نظيفة على جهاز جديد ليسا معتمدين. جاهزية العرض المحلي لا تعني جاهزية نشر عام.
- لا يوجد مستودع GitHub محدد حتى الآن؛ يلزم رابط المستودع قبل الرفع. لا ترفع الـZIP القديم لأنه لا يحتوي التعديلات الأخيرة.

## 8. الرفع من CMD

افتح CMD داخل مجلد النسخة المجهزة، لا داخل ملفات bin أو Frontend وحده. اتبع CMD-UPLOAD.md. لا تنفذ git add على مجلد مشروع آخر قبل التأكد من .gitignore. المستودع الواحد سيحتوي Backend وFrontend وREADME والصور.
